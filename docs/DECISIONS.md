**DB provider swap.** The Prisma schema says `provider = "sqlite"`. Prisma can't switch provider from an env var, so for the hosted Postgres deploy change that one line to `"postgresql"` and run `prisma db push`. `lib/db/index.ts` already picks the right driver from `DATABASE_URL`. We use `db push` (no migration files) during the hackathon so the provider swap doesn't produce a conflicting migration history. **TODO before Phase 4:** pick the host DB (Neon/Supabase free tier — check the expiry policy covers Dec 15).

**JSON and enum columns are plain `String`.** SQLite has no JSON/enum type in Prisma; storing JSON strings + validating with zod on read keeps one schema for both providers. Helpers: `lib/db/json.ts`.

**Money = integer cents**, converted only in `lib/money.ts`.

**Status machine** is enforced in code (`lib/guard/status.ts`): illegal transitions throw.

**PayPal mock mode.** `PAYPAL_MODE=mock` (or no creds + `DEMO_MODE=true`) swaps in `lib/paypal/mock.ts` so the whole flow runs locally before sandbox creds exist. Ids are prefixed `MOCK-` and the UI will show a "mock payments" chip. The hosted demo MUST run with `PAYPAL_MODE=sandbox`. Nothing presents a mock as a real PayPal result.

**Prisma's `init` drops agent skill folders** (`.agents/`, `.claude/`, `.windsurf/`, `skills-lock.json`) into the repo. Moved out so the submission stays clean; reference copy in the session scratchpad.

**AI runs only when the rules didn't already BLOCK.** If the deterministic policy says BLOCK, the AI verdict can't change the outcome (it can only tighten), so we skip the call and record "safety check skipped: already blocked by your rules". Saves ~2–8 s per blocked request.
